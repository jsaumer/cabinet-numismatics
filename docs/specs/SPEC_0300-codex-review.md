# Codex adversarial review of SPEC_0300

## Verdict

**Safe with changes.** The separate `cabinet_auth` schema, credential-free
archives, two-layer gate, fail-closed cookie CSRF rule, and photo subrequest
close the most likely anonymous collection leaks. Before approval, fix token
survival after password recovery, the archive-controllable restore marker,
the setup-code entropy claim, and login abuse paths that can keep the owner
out of a collection whose locations and values make read access especially
harmful.

## Add list

- **v0.30.0:** Revoke all tokens on password change and reset. This prevents a one-time password compromise from becoming durable inventory access.
- **v0.30.0:** Store the restore marker outside `public`, bind it exactly to the journal, and test a forged archive setting. This prevents backup-mount writers from steering recovery.
- **v0.30.0:** Add recent-password confirmation for backups, exports, tokens, secret settings, and restore. This limits damage from an unlocked laptop with a live session.
- **v0.30.0:** Reserve login capacity for a valid known device, cap audit stdout, rotate container logs, and let a correct setup code bypass only the setup delay. This reduces inexpensive LAN denial of service.
- **v0.30.0:** Alert on a new sign-in, a new device, token creation, backup download, restore start and finish, and sustained failed attempts. This gives the owner prompt evidence of a targeting attempt at modest implementation cost.
- **v0.30.0:** Use no-store for browser-viewed valuables data and clear browser cache and storage on logout. This reduces exposure on a shared or stolen device.
- **v0.30.0:** Restrict or withhold broad read tokens until there is a demonstrated automation need. A metrics token is sufficient for Homepage and Prometheus.
- **v0.31.0:** Require MFA through the OIDC provider for interactive sign-in, or add local WebAuthn or TOTP with recovery guidance. Password-only authentication is the remaining high-value remote compromise path.
- **v0.31.0:** Offer optional signed archives with a signing key outside the backup mount. This detects deliberate backup tampering, which checksums inside the archive cannot detect.

## Cut list

- **v0.30.0:** Cut the claim that a supplied `SETUP_CODE` can be proven to contain 128 bits from character diversity. Keep minimum format validation and generated-code defaults, but be honest that environment-secret entropy is an operator responsibility.
- **v0.30.0:** Cut stdout emission for every failed sign-in. Keep bounded audit evidence and sampled operational logging; otherwise the authentication endpoint becomes a log-volume denial-of-service tool.
- **v0.30.0:** Cut `FORWARDED_ALLOW_IPS` CIDR support from the initial UI and examples. Leaving it unset is simpler and avoids mistakenly trusting another container; the cost is less precise audit addresses.
- **Never:** Do not add a login-off switch, signed photo URLs, or photo-auth caching merely for convenience. Each weakens the boundary around the collection for little present benefit.

## Not verified

- `pg_restore --schema=public --clean` behavior on PostgreSQL 16 was not run. The brief permits throwaway Python routing checks, not a local Postgres restore exercise, and no live system was contacted. The stage 4 real-Postgres test must prove that `cabinet_auth`, its sequences, ownership, and its Alembic version are untouched.
- nginx normalization and `auth_request` behavior for encoded aliases and photo paths was not run. The current configuration has no auth request yet at proxy/nginx.conf:64-70. Stage 7 needs real-nginx cases for percent-encoding, dot directories, backend failure, and existing versus nonexistent photos.
- The live Swarm topology, Traefik behavior, NAS permissions, Docker log-driver configuration, and whether `SETUP_CODE` is visible to Portainer or Dozzle were not inspected. They are explicitly outside this checkout and must be reviewed against SPEC_0300 section 7 before release.
- Browser back-forward cache behavior after logout was not run across browsers. The cache recommendation is defense in depth for the explicitly in-scope unlocked-device threat, and stage 8 should prove it in Chromium at minimum.
